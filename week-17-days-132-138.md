## Reflection: Week 17

---

### The Mistakes We Made

#### 1. Birthday Sync ENOBUFS

**Cost:** Python birthday sync script crashed with ENOBUFS (buffer overflow) when processing Nexudus API responses
**Fix:** Rewrote from Python to TypeScript (`addfe913e`), which handled the data volume without issue
**Lesson Learned:** Python scripts for API integrations in a TypeScript ecosystem create maintenance burden. Standardize on the project's primary language.

#### 2. Nested Claude Session Detection

**Cost:** Multiple scheduled jobs failed silently because they inherited `CLAUDECODE` environment variables from parent sessions, triggering nested session detection
**Fix:** Four commits (`b74bfc585`, `3dba51e9d`, `389ffb548`, `35f2f518a`) stripped the env vars from all Claude CLI spawn points, plus a shared claude-invoker utility
**Lesson Learned:** Environment variable inheritance is invisible until it breaks. Scheduled jobs should explicitly clean their environment, not assume a clean slate.

#### 3. Luma Reminder Cascade Applied Backwards

**Cost:** Initial cascade implementation applied reminder config changes to events after the current time, not after the edited event - modifying past events
**Fix:** `906098313` limited cascade to events after the edited one, and `758e07a5d` further constrained to future events only
**Lesson Learned:** "Apply to all future events" has two definitions: future from now, or future from this event. The user always means "future from this event."

---

### The Surprising Things

#### 1. Notion Migration Created More Value Than Expected

**Expected:** Mechanical copy-paste of 42 items from Notion to the knowledge base
**Actual:** Every item improved during migration - policies expanded, templates generalized, archives curated

The migration wasn't a tax; it was an investment. A 4-rule dog policy became a full document. Two sponsor kits merged into one reusable template. 594 Sparkfile entries were curated into themed collections. The act of migrating forced decisions about what matters.

#### 2. iPostal Physical-Digital Gate

**Expected:** Standard digital confirmation flow for shredding requests
**Actual:** The flow enforced physical action before digital completion - you can't mark "shredded" until you've actually done it

This is the first time a workflow explicitly enforced physical-world actions before allowing digital completion. It's a pattern worth replicating for any workflow where the digital state should reflect physical reality.

#### 3. Voice Opt-In by Behavior

**Expected:** Voice replies would need a configuration toggle
**Actual:** The design "if you speak, I speak; if you type, I type" was more intuitive than any toggle

Matching the response medium to the input medium is the most natural UX. No settings needed.
