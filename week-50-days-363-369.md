## Day 367: Wake Promise Backstop, Braille UI, and Call-Agent Inbound Routing (October 3, 2026)

### The Wake Promise Backstop

**Commit `feat(stop-hook): add wake promise backstop for Discord sessions`**

You solved a persistent problem: responses that promise a later check-back ("I'll look at the logs tomorrow") but never set an agent_wake — turning the promise into a dead letter.

The Stop hook now scans the last assistant message for promise patterns: "I'll check/look/verify/report [action words] [tomorrow/tonight/in the morning/after it runs]." If it finds one and no wake was set this turn, it blocks Stop and asks you to create a wake now via the reminders-api skill. The hook only runs in Discord sessions (detects `DISCORD_THREAD_ID`), never loops (tracks whether it already ran this turn), and ignores promises inside quoted text or code spans.

This is a behavior contract enforced at the exit point rather than relying on memory.

### Braille Spinner and Status Icon System

The status icon system across wake, handoff, and context panels was unified around braille characters (⠿). A GIF generator was recreated with a `--color` flag (gold for active spinner). The handoff panel replaced 🟢 with a green-on braille icon on success. A `upload-jfdibot-emojis.ts` script was added to manage application emoji registration for the bot.

### Call-Agent Inbound Routing (GH #845, Early Commits)

Ask-user questions now post with one-tap Discord answer buttons that survive bridge restarts. Call outcomes get a Discord panel post. The thinking sound plays during ask_user lookups.

### Hook Reroute and Context Panel

**Lesson Learned:** Promises made at end-of-turn are structurally different from memory entries. They need enforcement at the exit point — a Stop hook that checks before the session closes — not a reminder that depends on a future session seeing it.

## Day 368: Call-Agent Voice Polish Marathon and SMS Andy Mode Launch (October 4, 2026)

### Call-Agent Voice Polish: Ring, Greeting, and Sound (GH #845)

**Commits `e33bc2a015`, `12187c5926`, `bb20202775`, `86b62e15c3`, `cdb97fd361`** and ~20 more

The Saturday sprint was the largest single-day call-agent effort yet. Every aspect of the call-in experience was touched in sequence:

**Ring behavior**: The ring now loops until the voice model is actually ready to speak, with a 12-second cap (down from 15s). A handset pickup click plays before the greeting. The ring's echo was muted so the greeting isn't doubled. A short pause between the click and the greeting prevents them from running together.

**Greeting improvisation**: The scripted "Hey Alex, what's up?" was replaced. The voice now improvises a breath, "mm", beat, or throat clear before the hello — making it sound like a person picking up, not a recording starting (`bb20202775`). The low-key greeting flavor was dropped entirely (`be68dbf495`).

**Thinking sound**: Three candidates were auditioned through the actual phone chain. Alex picked R3: calm typing with natural pauses, 6 seconds long (`e33bc2a015`). It sounds like someone looking something up, not a placeholder loop.

**Holding lines**: Digging words removed from holding lines. Lines start on the statement (no "yep" or "okay" lead-in). The voice ad-libs its checking line once; the back office never acknowledges it. Upbeat framing, answer-first time budget.

**Mute sequencing**: Caller's audio is muted until the greeting plays (`5b17a6b606`), then unmuted once the greeting's sound ends (`261170a0c6`).

**Shared voice rules**: Refactored into `voice/shared.ts` with the "in the call notes" claim dropped (`cdb97fd361`).

### SMS Andy Mode Launch (GH #862)

**Commits `e49c62cf8a`, `08e1a7a575`, `fd935b4b86`, `f903f745dc`, `50d37e1d7e`, `eebc0ef9f7`**

The SMS Andy mode launched after weeks of groundwork. The full design:

**Safety gate** (`e49c62cf8a`): A PreToolUse hook limits what text-originated turns can do. Owner text turns can't pay, call, touch door codes, Brivo, credentials, or git push. Contact turns are read-and-draft only.

**Andy mode** (`08e1a7a575`): `/andy on|off` per one-on-one thread (owner only). sms-server gets an `andy_mode` column. `/sms/andy-threads` returns registered threads. `/sms/andy-reply` sends owner-thread replies (three-text cap, buttons as a numbered list). Turn markers distinguish owner turns from contact turns.

**Reply relay** (`fd935b4b86`, `f903f745dc`): The Stop hook relays owner-turn replies back through sms-server. Deduped per turn. Reads the reply from the Stop input payload — not the transcript, which writes after hooks run.

`/andy on` is restricted to Alex's own text thread for now (`50d37e1d7e`). The new-thread skill refuses to move an Andy SMS thread to avoid breaking the relay (`eebc0ef9f7`).

### Other Day 368 Work

- **jfdi-context mod** (#857 steps 3-4, `f867c837d2`): context-warning ported to a mod running in shadow mode with characterization tests. Loaded in interactive claude sessions via zshrc (`44d104edd0`).
- **write-size-guard** (#852): hook keeps individual Write calls under the size limit; loaded in the claude wrapper.
- **Watchdog** (#861, `4c021d5f34`): alerts on Claude memory, classifies sessions by JFDI_SLOT so Haiku one-shots stop counting as interactive sessions.

## Day 369: SMS Tapback System and Webhook Security Hardening (October 5, 2026)

### Jev Tapback System (GH #862)

**Commits `183f9c18fa`, `6da7a2f789`, `d127a388d0`, `43f34894fa`, `a3ee14c636`, `ee0b632e5f`**

Sunday's 20+ commits were entirely focused on refining the tapback and reply system:

The tapback lifecycle now runs in three stages. When a text arrives, Andy immediately sends a 👍 acknowledgment (`183f9c18fa`). While Andy is processing, the 👍 swaps to 👀 (`6da7a2f789`). When Andy is done, the 👀 is replaced by a fitting emoji chosen by Jev (`d127a388d0`).

Jev — the tapback selection model — picks the single tapback a text gets. Topic-based selection with strong tone winning over the topic signal (`a3ee14c636`). The confidence floor was dropped so split-confidence picks aren't forced to 👍 when the text is clearly something else (`ee0b632e5f`). Andy no longer swaps the tapback after Jev sets it (`43f34894fa`).

### SMS Andy Mode Polish (GH #862)

Other hardening across the day:
- **GSM-7 budget**: Andy replies are budgeted by SMS part count, not character count — the right unit for carrier billing.
- **Repeat text dedup**: 2-minute window catches resends.
- **Context exhaustion**: when a text turn runs out of context, the answer is held and texted after the session ends.
- **Avatar distinction** (`8f8c17e6fc`): Alex's texts post with his Discord avatar; Andy's texts post as JFDIBot — visually distinct in the thread.
- **Useful links** (`93048aee12`): text replies include useful links without being asked, using the voice agent's lookup strategy.

- **Replay with accurate timestamps** (`5bb51fc38a`, `7c28f0ca5d`): texts that arrived while sms-server was down are replayed showing when they were actually received, not the replay time.
- **Still-digging**: "still digging" texts go out on the thread's own line, not inline with other content.
- **Reply discipline** (`6c29876997`): the reply rule answers the exact question, no trailing offers.
- **Lookup discipline** (`f291b93c98`): search previews are leads, not facts — no stitching multiple results into a single confident claim.
- **SOPs**: contact-thread decisions (`958e26afb2`) and the procedure for wiring Andy mode onto another thread (`e9ea13f689`) were both documented.

### Telnyx Webhook Security Hardening

**Commits `d942f6a39c`, `b1840604ae`, `a4c1ce3c04`**

The SMS webhook had a critical gap: it skipped the Ed25519 signature check when no signature header was present, meaning anyone could POST a fake inbound text into a Discord thread.

`d942f6a39c` closed it: a missing signature or timestamp → 403; a timestamp more than five minutes old → 403; a missing public key → 403. The check is enforced before any message routing happens.

`b1840604ae` tightened the Caddy layer: only Telnyx's webhook paths of sms-server are publicly accessible. Everything else is behind the normal auth wall.

`a4c1ce3c04` followed the audit-before-gate pattern established earlier in the week: log signature headers on the call paths before gating them, giving 24 hours of data to confirm Telnyx's actual signing behavior before the gate goes live.

**Lesson Learned:** An Ed25519 check that skips when the header is absent is equivalent to no check. The missing-header case is precisely the forgery path. Any signature validation must treat "no signature" as invalid, not as a permissive default.

## Reflection: Week 50

---

### The Mistakes We Made

#### 1. Reply Relay Read the Transcript Instead of Stop Input

**Cost:** First replies were silently dropped every new session. The Stop hook fired, read `~/.claude/projects/.../transcript.jsonl`, found nothing (the file doesn't exist until after hooks finish writing), and texted nothing. The bug was invisible — no error, no alert, just silence.\
**Fix:** `f903f745dc` — relay reads `last_assistant_message` from the Stop hook's stdin payload instead of the transcript file.\
**Lesson Learned:** Hooks run before the transcript is written. Any hook that reads the transcript to get the last response will drop the very first response every time. Use the hook's input payload.

#### 2. SMS Webhook Accepted Unsigned Requests

**Cost:** Anyone who could construct a valid POST body could inject a fake inbound text into a Discord thread and trigger Andy mode. The check existed for signed requests but the unsigned case — the forgery path — was silently permitted.\
**Fix:** `d942f6a39c` — missing signature, expired timestamp, or missing public key all return 403.\
**Lesson Learned:** Signature validation that permits unsigned requests provides no security. The missing-signature case is the attack path. Treat absence of a signature as an explicit rejection, not a default pass.

---

### The Surprising Things

#### 1. The Thinking Sound Needed an Audition

**Expected:** Pick a reasonable ambient sound, ship it, move on.\
**Actual:** Three rounds of real-phone auditions were needed before landing on R3. The problem wasn't subjective taste — different sounds changed the feel of the call in ways that only became clear through the actual phone chain. A sound that sounded fine on speakers felt wrong through a phone earpiece. Alex's direct participation in the audition produced the right result in a way that no internal review would have.

#### 2. Reply Links Work Better Inside Text Than as Separate Messages

**Expected:** Sending each link as its own text message would make links easier to tap.\
**Actual:** It fragmented the reply into an awkward multi-message sequence that felt broken. The experiment shipped and was reverted in the same day. A single reply with embedded links reads as one coherent message; split links read as a malfunction.
