## Day 279: Meeting Replay Gets Its Builder + Event Sync Simplified (July 7, 2026)

### TypeScript HTML Builder and Replays Gallery

**Commits `96283a8699`, `14d0b58bb8`, `c13910dfa4`, `a0bb149720`, `798fccbb09`**

You built a TypeScript HTML builder for meeting replays (`96283a8699`, GH #351): a script that assembles the full replay HTML from structured fields — OG tags, sticky player, sections, action items — without depending on Claude to format the page manually. The builder became the canonical output contract; any pipeline step writing a replay page calls it rather than constructing HTML by hand.

GH #355 items 3–6 followed: friction elimination across the skill — steps were reordered, narration between status lines was suppressed, CLI fallback in Step 2 replaced the MCP call that was failing in certain contexts, and the clear script gained a `--vm` flag and a re-post that fires immediately after state reset.

**Lesson Learned:** A pipeline that depends on the model to format its output is fragile — the format drifts as prompts evolve. A builder script with explicit field inputs is the right abstraction; the model generates data, the script generates HTML.

### Event Sync Simplification (GH #354: Steps S3–S5)

**Commits `7d17d28bdb`, `a72ec12a20`, `a9ec48c96d`, `b9db68c08b`**

Three simplification steps landed in sequence: `7d17d28bdb` deleted the entire GCal iCal sync path — 570 lines that handled an approach deprecated when native API sync arrived. `a72ec12a20` (S3) removed conflict machinery and the `source_of_truth` column. `a9ec48c96d` (S4) collapsed three separate outbound triggers (`pushToGcal`, `syncToGcal`, `updateGcal`) into a single `reconcileGcalPush` function. `b9db68c08b` (S5) stored `primary_calendar_event_id` directly on the event record, eliminating repeated GCal searches on every sync cycle.

**Lesson Learned:** When a codebase has three functions that do almost the same thing, the fix isn't to pick the best one — it's to identify what they're all trying to say and write that directly. ## Day 281: The Gate Bug Marathon (July 9, 2026)

### Twenty Commits to Fix One Cluster

**Commits `b3049299d1`, `c309ace9d4`, `788745e5d3`, `ddb56a5b7a`, `678040fbc6`, `9d9a28b648`, `167063b1e1`, `20dc161708`, `0e6fa1ecb6`, `9f5d58eab3`, `4c06daa5b2`, `0a77db4c69`, `196378a4c7`**

July 9 was the biggest debugging day of the week — possibly of the past month. The suggest-options gate had accumulated a cluster of failure modes in jfdi mode, all producing the same symptom: doubled Discord posts or missing content.

The root causes, discovered in sequence:

1. **GH #369**: Gate wasn't enforcing visible text before suggest-options buttons — buttons could appear with no explanation above them
2. **GH #370**: `hadStreamedBeforeSuggestOptions` didn't work in jfdi mode because text and `tool_use` arrive in the same assistant chunk, so `postedMessageIds` is empty at detection time
3. **GH #373**: Side-channel file was only written in `flushIncrementalText`, missing writes from `text_delta` events — fixed to write on every text event
4. **Gate**: Side-channel race between the hook and andy-chat — fixed with retry-read logic
5. **Idempotency key**: Wasn't persisted across `postToDiscordThread` retries, enabling doubled messages on HTTP timeout
6. **Concurrent same-key double-post**: A pending sentinel prevents two simultaneous posts with the same idempotency key
7. **Pre-await sentinels**: For spinner, blocked-embed, and compaction — three separate idempotency gaps

The test suite went from fragile to 13/13 + 15/15.

**Lesson Learned:** A cluster of bugs that all produce the same symptom (double post) with different causes requires a test suite that can distinguish them before any fixes ship. Writing the repro suite first made it possible to confirm each fix in isolation rather than guessing which of seven root causes a given commit addressed.

### Meeting Catalog and Replays Gallery

**Commits `c13910dfa4`, `925f7ff56b`, `798fccbb09`**

The `catalog.json` meeting register was wired to update on every replay publish. The TypeScript rewrite made the catalog script deterministic and testable. The `/meetings/replays` gallery page pulls excerpt, title, and date from the catalog — a browsable index of all published replays.

**Lesson Learned:** A machine-readable catalog is worth building once the second replay is published, not after ten. The cost of adding the `upsert` call to the publish pipeline is trivial; the value of having a gallery compounds immediately.

### Voice Memo Two-Mode Sync

**Commit `45f21be2fb`**

The voice memo watcher gained a two-mode sync pre-flight: standard mode (15-minute window, production cadence) and testing mode (1-minute window, for development without a 15-minute wait). The mode selection is documented in the SOP and defaults to standard.

**Lesson Learned:** A development workflow that requires production cadence is a workflow you'll bypass. An explicit testing mode with documented parameters is the correct safety valve.

**Commits `65735530f5`, `441b0efb59`**

## Day 283: Credential Security Overhaul + Context-Aware Nudge Engine (July 11, 2026)

### The Credential Scanner Learns to Think for Itself

**Commits `5bde95b14d`, `1a04c76ab2`, `7b5d86f0aa`, `437fbbcd15`, `58f8c02fb8`, `d8e0e10963`, `4a4d6f4408`, `fc248e52a7`**

The credential protection system underwent a full overhaul in one session:

- **Auto-pattern generation** (`5bde95b14d`): `generate-credential-patterns.cjs` fetches masked previews from `/proxy/v1/credentials/inspect-all` and writes `credential-patterns.auto.cjs`. The scanner's detection rules are now derived from the actual credentials in the database rather than maintained by hand
- **Auto-trigger on change** (`1a04c76ab2`): Every save or delete to the credentials DB triggers a pattern regeneration, so the scanner is always current without a manual step
- **8-char prefix** (`7b5d86f0aa`): Prefix length increased from 4 to 8 characters — 4-char prefixes were colliding with Claude Code session UUIDs, producing false positives
- **Unified PostToolUse hook** (`58f8c02fb8`): Two separate credential output guard scripts (`credential-output-guard.sh` and a prior unified version) collapsed into one PostToolUse hook covering Bash, Read, Grep, and WebFetch
- **Auto-scrub on hit**: The scanner now applies inline redaction to file-based credential hits rather than just alerting, making it self-healing for the common case

The SOP documenting the full architecture was published at `docs/security/credential-protection-system-sop.md`.

**Lesson Learned:** A security scanner that requires its detection patterns to be manually maintained will always lag the actual credential set. Deriving patterns from the database at save time is the only approach that stays current without process overhead.

### Context-Aware Nudge Pipeline (GH #385)

**Commits `b6a4e4522f`, `a6812344a4`, `f195ca149e`, `65ec71de4a`, `2c2370bb5f`, `dea9466e7f`, `ce74b5a590`**

The relationship nudges system had posted the top-3 contacts by urgency score — a static formula that ignored open promises, life changes, and calendar context. GH #385 replaced it with a four-stage context-aware pipeline, built completely in one session:

- **Stage A** (`b6a4e4522f`): `normalize.ts` maps 33+ priority variants to a stable enum; `signal-scan.ts` reduces 680+ candidates to ~40 with meaningful signals (life changes, open promises, events)
- **Stages B+C** (`a6812344a4`): `assemble-context.ts` builds a 40-person candidate pool from live events API, active workstreams, and operator status. `select-llm.ts` makes one Sonnet call with structured output, validates picks against card content (hallucination check), rejects canned openers
- **Wiring** (`f195ca149e`): `--smart` flag connects the pipeline to the 2pm scheduled run; zero picks posts nothing rather than sending an empty embed
- **OOO auto-expiry** (`65ec71de4a`): `operator-status.json` checks `available_from` date and self-heals when the return date passes — no manual clearing required
- **Output routing** (`dea9466e7f`): Reconnect picks route to `#workbench` (action channel) instead of `#system-notifications` (log channel)

The formatter gained `formatReconnectPickEmbed()` — a warm amber embed with `why_now`, a starter outline, and a metadata line rather than the old score dump.

**Lesson Learned:** An LLM-based selection step with a hallucination check (validating picks against the actual candidate card content) is significantly more trustworthy than prompting the model to "pick the best contacts." The validation step makes it safe to surface the result directly to the user.

### Two-Part JFDI Duplicate Fix (GH #391 + #374)

**Commits `47b13c320d`, `d6a28cb674`**

Two commits closed the jfdi-mode duplicate bug that had been narrowed but not eliminated:

- **`47b13c320d`** (GH #374): In the bridge flush handler, when `msgLen > 0` in jfdi mode, the side-channel file is read before posting — if it shows streamed content for this thread and `lastMessageId` exists, patch buttons only. ### The Mistakes We Made

#### 1. Steer Experiment: Shipped to Main, Reverted in 24 Hours

**Cost:** Five commits building the Haiku auto-judge mid-turn routing all went to main. Unexpected production timing issues appeared that weren't visible in development — the judge spawn was racing thread state needed by downstream handlers. Five more commits reverted all five, and the feature branch now exists as context for a future attempt.\
**Fix:** All five steer commits reverted with `8c38f19b5e`; feature preserved on `feature/steer-experiment`.\
**Lesson Learned:** Any feature that fires on every `message_stop` in a high-traffic path needs staging before main. "It worked in development" is insufficient verification for a path that touches thread state under concurrent Discord traffic.

#### 2. Travel Data Structure: Per-Trip Index, Then Reverted Same Day

**Cost:** `11822b114d` introduced per-trip `index.json` files alongside a slim global registry. The same day, `a84c2d6de1` reverted to a single fat `_index.json`. The per-trip approach added complexity without clear benefit at the current scale (one trip).\
**Fix:** Reverted to single file in the same commit session.\
**Lesson Learned:** Premature structural generalization creates churn. A single file is correct until the second file proves it isn't. Don't design for hypothetical future trips before the first trip is fully useful.

#### 3. The Gate Bug Cluster: 20+ Commits to Close One Symptom

**Cost:** The suggest-options gate in jfdi mode had at least seven distinct root causes all producing the same symptom (doubled Discord posts). They accumulated over multiple sessions and required a full dedicated debug day (July 9) with 20+ commits to resolve.\
**Fix:** Test suite added (13/13 + 15/15 passing), each root cause fixed and verified in isolation.\
**Lesson Learned:** When the same symptom recurs after fixing a known cause, the problem is a cluster, not a single bug. Stop debugging symptom instances and enumerate root causes systematically. A test suite that distinguishes them is the prerequisite to fixing any of them.
