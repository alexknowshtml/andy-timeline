### The Mistakes We Made

#### 1. The Silent Semantic-Search Degradation

**Cost:** pgvector queries throwing PHP exceptions surfaced as Whoops HTML pages. The JS layer parsed the HTML as JSON, got a `SyntaxError`, returned `[]`, and starved Andy sessions of memory recall — silently. No error logged, no Discord ping, just Andy "seeming forgetful." Combined with a Haiku probe occasionally emitting graph patches with unknown `domain` values that crashed `applyPatches` on `undefined.nodes`.\
**Fix:** `e01822424` — `VALID_DOMAINS` whitelist guard before `graph.domains[patch.domain]`; pgvector query wrapped in PHP try/catch so exceptions return JSON, not HTML; tinker output validated to start with `[`/`{` before `JSON.parse`, with first 200 chars logged on non-JSON for future diagnosis.\
**Lesson Learned:** A silent failure that returns "no results" is more dangerous than a crash. Any `JSON.parse` on subprocess output should peek at the first character before parsing. Symptom-only bugs ("Andy seems forgetful lately") need *log* fixes, not just *behavior* fixes — the first 200 chars on failure is the trace that catches the next variant of the bug.

#### 2. The Same Bug in Two Scheduled Jobs

**Cost:** `monthly-memory-health.cjs` had been showing blank Discord threads when the audit session ended with a Bash tool call (e.g., `suggest-options.sh`) — the `resultEvent.result` only captures text *after* the last tool call. The bug also lived in `morning-overview.cjs`, undetected.\
**Fix:** `eef27b1a3` (monthly-memory-health) + `26e785924` (morning-overview) in the same session — both now collect text from all assistant message content blocks instead of just the result event.\
**Lesson Learned:** When a scheduled job has a bug, grep the rest of the scheduled-jobs directory for the same pattern before moving on. A bug shape (`resultEvent.result` only captures post-tool-call text) repeats; the fix should be a *grep + apply* pass, not a one-off.

#### 3. The Display Color Round Trip on Clubhouse dB Meter

**Cost:** Initial display rendering on the M5Stack StickS3 produced wrong colors. Four commits to fix: `color565()` channel correction → TFT_ constants instead → `setSwapBytes(true)` for the GC9107 chip → `uint32_t` → `uint16_t` in `updateDisplay()`. Each fix surfaced what the prior fix had missed.\
**Fix:** `9b1476bbd` (final fix) — `uint32_t` → `uint16_t` was the actual root cause; the chip was reading 32-bit values as 16-bit, producing channel swap that *looked* like a color order issue.\
**Lesson Learned:** Color rendering bugs on embedded displays are usually byte-width or byte-order, not RGB-vs-BGR. Check the type signature of `updateDisplay()` before reaching for `setSwapBytes` or `color565()`.

#### 4. The FFT Spectrum That Wasn't Worth It

**Cost:** Half a dozen commits adding an FFT spectrum visualizer (full-screen toggle, segmented spectrum, flicker fixes via per-segment painting, float FFT, BtnA/BtnB toggle) — then reverted to "pre-FFT VU bar only."\
**Fix:** `885ba87c9` — Revert. The VU bar is more legible from across the room than the spectrum, and the FFT was the wrong abstraction for "how loud is the room right now."\
**Lesson Learned:** Spike → revert is a valid outcome for hardware UI work. The FFT exploration proved the VU bar was the right answer — that's the value of the spike, even when it ends in `git revert`. Don't treat reverted commits as wasted; treat them as the experimental evidence that the simpler design was correct.

#### 5. The Pretty-Page TOC Round Trip (Open-Then-Closed-Then-Open)

**Cost:** Three commits in 11 minutes (`199d2b0d2` → `5e919448c` → `5fcfaf540`): collapse center-column TOC by default, revert, collapse cleanly. Confusion between the new floating-sidebar TOC and the existing center-column TOC.\
**Fix:** `5fcfaf540` — Final clean implementation that distinguishes the two TOCs.\
**Lesson Learned:** When a feature has two visually similar variants (sidebar TOC + center TOC), name them distinctly in code so the next round of changes doesn't accidentally affect the wrong one. A round-trip is a signal that the abstractions are too close to each other.

### The Surprising Things

#### 1. A Hardware Day Produces 30+ Commits, Not 3

**Expected:** Adding a new IoT device would be one or two commits — initial code + a tweak\
**Actual:** The Clubhouse dB Meter shipped on Day 221 with 30+ commits in a single Sunday afternoon: 4 display color fixes, 8 display redesign iterations, 7 FFT spectrum commits (then reverted), 4 final hardening commits, plus skill docs, calibration, BtnA menu, ThingSpeak boot fix, WiFi self-heal.

The compounding lesson: a hardware *day* is 25%-build, 50%-tune, 25%-revert. Schedule hardware work in chunky multi-hour blocks, not 30-minute slots — the tune cycle won't fit otherwise.

#### 2. The AI Hero Email Corpus Was Already in /tmp

**Expected:** Building an archive of 67 newsletter emails would require gmail API calls, parsing, writing\
**Actual:** The 67 emails were *already* in `/tmp` from prior work — the archive was a *consolidation* (move + dedupe + restructure) rather than a fresh extraction. The actual extraction work happened on Day 219's later raw-MIME rebuild (`4e0a8c248`) which preserved 3 inline images + 54 content links that the plain-text version had stripped.

The compounding lesson: the second pass on data extraction (raw MIME with HTML→markdown + click-tracker URL decoding) is qualitatively different from the first pass (plain text). When archiving long-form content, plan for the rebuild from raw — the first pass loses formatting.

#### 3. Tailscale BIND_HOST Turned a .env Tool Into a Credential Collector

**Expected:** A fork of `agent-secret-manager` would replace `.env` writes with credential store writes — a small adapter\
**Actual:** The fork added `BIND_HOST` env var so the web UI can listen on the Tailscale IP, making it reachable from the human approver's phone or laptop *without* exposing it on the public internet. The combination (Tailscale-reachable + writes to credential store + scope/team/user form fields) turns it into a *human-approver credential collection workflow* — not just a credential editor.

The compounding lesson: small infrastructure changes (BIND_HOST, scope fields) can change the *use case* of a tool, not just its target. The fork's value is the workflow it unlocks, not the lines of code it adds.

#### 4. A 5-Part Framework Encodes Better Than a Skill File

**Expected:** Documenting Alex's high-stakes client message pattern would be a long SKILL.md with examples\
**Actual:** The `strategic-client-question` skill (98 lines) is structured as a 5-part numbered framework: lead concrete → validate emotion → 3 options including emotional → ask without pre-arguing → close with strategic frame. The frame is short enough to recall mid-conversation, deep enough to apply in novel situations.

Similarly, `stb-email-editor` Mode 5 (Strategic Client Message) is the same 5-part framework wired into the email editor — same pattern, two surfaces.

The compounding lesson: a numbered framework with 5 verbs beats a 500-word "how to" — it survives compression and can be scanned mid-flow.
