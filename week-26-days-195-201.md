## Day 196: Event Reminder Timezone Fix & the Tokens Explainer (April 15, 2026)

### The UTC-vs-ET Bug That Shipped "10 PM EDT" for 6 PM Events

**Commit `3597d3449`**

A bug in `EventReminder24h` and `EventReminder3h` mail was formatting UTC-stored `slot_start`/`slot_end` times directly as UTC, then appending the correctly-converted timezone abbreviation. The result: "10:00 PM EDT" in emails for an event that actually started at 6 PM ET. The same bug was in `CalendarLinkService::icsContent()` — UTC times labeled with `DTSTART;TZID=America/New_York`, causing calendar imports to land 4 hours off. Fix: convert to event timezone before formatting. Shipped alongside event reminder infrastructure that had been running in production.

The git-hygiene workflow gained auto-gitignore for nested git repos and an alert on unknown untracked directories — catching the pattern where external repos get cloned into the tree and clutter up `git status` without being tracked or ignored.

### SleepMe DB Recovery

### do-upload Returns Public URLs

### The Mistakes We Made

#### 1. The UTC-vs-ET Event Reminder Bug

**Cost:** Event reminder emails displayed "10:00 PM EDT" for events that actually started at 6 PM ET — a 4-hour display error that shipped into production. iCal imports were similarly off because DTSTART was UTC but TZID was labeled America/New_York.\
**Fix:** `3597d3449` — Convert slot_start/slot_end to event timezone before formatting in both `EventReminder24h`, `EventReminder3h`, and `CalendarLinkService::icsContent()`\
**Lesson Learned:** When the storage format and the display format disagree on timezone, the bug won't surface in local dev if you're in the same zone. Convert at every boundary, not just at final display.

#### 2. Archive Script Deleted Before Upload Confirmation

**Cost:** The `archive-claude-sessions.ts` script deleted sessions from source after what it *thought* was a successful upload — but the upload confirmation was implicit, not verified. Lost data.\
**Fix:** `212858f60` — Formal archive script safety SOP (transfer → confirm → delete pattern) + incident comment + safety gate in the script\
**Lesson Learned:** "Already exists at destination" is NOT sufficient confirmation to delete from source. Gate deletion on an explicitly-returned confirmed-upload boolean, not an implicit success path.

#### 3. Host-Bridge Typing Interval Leaks

**Cost:** Multiple Claude spawns hitting the same Discord thread created orphaned typing intervals. Zombie "Andy is typing..." indicators accumulated across sessions. The CROSS-TALK detection was also registering 'unknown' as a thread owner.\
**Fix:** `e6a5c6031`, `40c1bcbff`, `54ea7ff15` — Three fixes in one evening: clear interval before register, identity-check before cleanup delete, skip 'unknown' in thread owner registration\
**Lesson Learned:** Interval maps leak when registration isn't idempotent. Always clear existing before registering, and identity-check before cleanup delete.

---

### The Surprising Things

#### 1. The --only Flag Bug Was Hiding in Safe-Restart Itself

**Expected:** The `pm2-safe-restart.sh` wrapper was the defense against the PM2 --only flag bug\
**Actual:** The wrapper itself was using --only. The Day 198 retrospective surfaced it — the very script meant to prevent the bug was the offending caller. Fix was to replace every `pm2 start --only` with direct `pm2 start` that mirrors the ecosystem config.

The lesson that compounded: bugs live where you stop looking. "Safe-restart" was trusted because of its name, not verified.

#### 2. A Scheduled Job from 5 Months Ago Had Zero Invocations

**Expected:** The relationship-warming-detector agent was built in November and quietly doing its job\
**Actual:** Zero invocations. The agent existed, worked in testing, but was never wired to a schedule. RDC-001 surfaced in the system-gap detector report: agent built, agent forgotten.

The fix was binary: add a Monday 7am cron, route output to Discord. The gap detector caught what 5 months of audits had missed — because "agent exists" was being confused with "agent runs."

#### 3. UI Polish Compounds Across Every Document

**Expected:** Jakub Krehel's "Make Interfaces Feel Better" guide would be a reference bookmark\
**Actual:** Within hours, its principles were applied to the pretty-page template — meaning every future generated document inherits font smoothing, proper text-wrap, specific transitions, press feedback, and 40px hit areas.

One guide → one template update → every future output is better. The compounding point was higher up the stack than expected.
