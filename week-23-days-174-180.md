## Overview: Intelligence at Every Layer

Week 23 was about making Andy smarter at every level of the stack. The **model delegation layer** shipped in two phases - scheduled jobs defaulted to Sonnet, the Discord bridge gained smart escalation logic, and by week's end **Discord model control** let users choose which model handles their requests in real time. Meanwhile, **pretty-page evolved from a renderer into a platform** with collapsible TOC, localStorage-backed interactive checkboxes, floating copy buttons, anchor links, and metadata styling - receiving 30+ commits across the week. On the infrastructure side, a **PM2 durability overhaul** produced hardened restart scripts, a dump audit tool, and the `/restart` skill. The **PM2 watchdog moved from Bree to systemd** after discovering it could kill its own parent process. A **session source field** broke a classification feedback loop that had been contaminating Andy Insights data. And the week opened with the **iMessage context capture** system maturing, automatically filing conversation summaries into person files and committing them on every sync cycle.

**Key themes:** Model delegation and routing, Discord model control, pretty-page platform, PM2 fortification, systemd watchdog, session source field, newsletter shipping, iMessage context capture.

## Day 179: Session Source Field & The Systemd Migration (March 29, 2026)

### Session Source Field: Breaking the Feedback Loop

**Commits `dd97790a8`, `1e94292a7`, `5c53ce671`, `e31f3a586`**

Andy Insights had a contamination problem: automated sessions (scheduler runs, watchdog jobs) were being classified as meaningful interactions and skewing the facet extraction data. The fix was a 3-phase session source field implementation:

1. **Phase 1**: Added `source` field to sessions table, populated from hook payloads (`startup` vs `resume` vs `scheduled`)
2. **Phase 2**: Updated classification logic to filter automated sessions by source instead of fragile `user_messages LIKE` heuristics
3. **Phase 3**: Verified the feedback loop was broken - the same automated sessions that were triggering extraction were now correctly skipped

Session counts in the UI were also cleaned up: duplicate counts hidden unless filters are active (`1432d5266`), automated sessions kept visible in token usage totals (`a804bc679`).

### PM2 Watchdog Migrated to Systemd

**Commit `7ebfe89cd`**

The PM2 service watchdog moved from the Bree scheduler to a systemd user timer. The reason: the watchdog was occasionally killing its own parent process when recovering the scheduler service - it didn't know it was running *inside* the thing it was trying to restart. Running it from systemd (outside PM2 entirely) eliminated the self-destruction risk.

### Graceful Usage Limit Handling

**Commit `08b8b83bb`**

Scheduled jobs now handle Claude API usage limit errors gracefully - detecting rate limits and quota exhaustion, logging them distinctly, and backing off without crashing. The git-hygiene job also gained submodule cleanup and usage limit handling (`363aebf7e`).

### Facet Extraction Zombie Fix

**Commit `7c70dd76c`**

Facet extraction jobs that timed out were leaving zombie `claude --print` processes attached to the host-bridge. The fix: explicit process cleanup on timeout, with SIGTERM followed by SIGKILL for stubborn processes.

### Three Scheduler Job Failures Fixed

**Commit `55d3bc008`**

Three scheduled job failures addressed in a single commit: an unhandled throw in facet extraction was crashing the host-bridge process itself (not just the job), a NULL-safe comparison bug in the memories catch filter was silently dropping results, and ANSI escape codes from PM2 status output were breaking the safe-restart script's status parsing (`1e94292a7`).

### Newsletter March 30 Edition

**Commits `9dc481198`, `45c6cd759`**

The March 30 newsletter was built with an ICE Out / Saval spotlight (adding Philly immigration advocacy context) and Victoria's story refined with a personal quote and image.

**Lesson Learned:** When a feedback loop contaminates your training data, you don't just get wrong answers - you get confidently wrong answers. The session source field is a guard against the system learning from its own noise.

## Reflection: Week 23

### The Mistakes We Made

#### 1. PM2 Watchdog Killing Its Own Parent

**Cost:** The PM2 service watchdog was occasionally restarting the Bree scheduler - the process it was running inside. This caused unpredictable cascade failures where the watchdog would trigger, then get killed mid-recovery, leaving services in a half-restarted state.\
**Fix:** `7ebfe89cd` - Moved the watchdog from Bree to a systemd user timer, running completely outside PM2's process tree\
**Lesson Learned:** A watchdog that runs inside the process it monitors can't be trusted to recover it. The guard must be at a level above what it's guarding.

#### 2. Ghost Sessions Contaminating QMD Semantic Search

**Cost:** Sub-agent sessions shared `discord_thread_id` with their parent sessions, causing them to appear as high-similarity "ghost" matches in semantic search results. Users would get relevant-looking results that referenced agent-to-agent communication rather than real conversations.\
**Fix:** `74fb2b436`, `47ff20d72` - Server-side weight application and hard filter (< 0.5 weight) from all semantic search paths\
**Lesson Learned:** When sub-agents inherit parent metadata, they inherit parent searchability. Explicitly mark internal sessions as internal, or they'll pollute user-facing search.

#### 3. Classification Feedback Loop in Andy Insights

**Cost:** Automated sessions (Bree jobs, watchdog) were being classified as meaningful interactions and fed back into the facet extraction pipeline, skewing session analytics data.\
**Fix:** `dd97790a8`, `5c53ce671` - Session source field with 3-phase implementation\
**Lesson Learned:** Analytics systems are only as clean as their input filters. When the system generates its own data, it needs explicit exclusion rules before that data enters any learning or analysis pipeline.
