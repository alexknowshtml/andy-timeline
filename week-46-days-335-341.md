## Day 337: The Silently-Dead Hook and the Instant Boundary Panel (September 3, 2026)

### The Orphan Brace That Killed Context-Warning

**Commit `18ee4e6205`** (fix: remove orphan brace that silently killed context-warning hook)

An orphan closing brace in the context-warning hook was discovered — it had been silently short-circuiting the entire hook on certain execution paths. The hook appeared to run but exited early without acting. The bug's presence for an unknown period meant the handoff engine had a hole: some sessions were escaping the early-warning path entirely.

The same day: pre-turn guard, context-exhaustion recovery logic, and stderr logging were added to the hooks system (GH #644, `9129546f02`) — hardening the execution boundary so future hook failures produce visible errors instead of silent no-ops.

### Instant Boundary Panel with Hourglass Spinner

**Commit `0d171b3600`**

The boundary panel previously waited for Haiku to finish writing the handoff message before appearing. That created a gap: the user saw nothing while Haiku worked. The fix: post the boundary panel immediately when the handoff arms — with a `⏳` hourglass spinner and a typing indicator — then update it with the real content when Haiku finishes. The session transition now has a visible start, not a silent pause followed by an announcement.

### LIFT Philly: Kit-to-Turso Testimonial Sync

**Commit `7e7f288192`**

A sync script landed to pull Kit petition signers into the Turso testimonials database (`run-sync-lift-testimonials.sh`). Coalition members in Kit who've signed the petition now flow automatically into the testimonial system without manual imports.

**Lesson Learned:** A hook that exits silently on failure is worse than a hook that crashes loudly. Silent failure hides that anything is broken. Any hook path that does nothing should log why — the default should be visibility, not quiet exit.

## Day 339: Sonos Gets a Brain (September 5, 2026)

### Dynamic Fallback Chain Watchdog

**Commit `5c6d6e0c4a`**

The Sonos watchdog was rewritten from the ground up with a coordinator-aware fallback chain: Main → Kitchen → Skyroom. When the tracked coordinator goes offline and doesn't return within the boot timeout (3 minutes), the watchdog promotes the next alive eligible speaker automatically — rather than just alerting and waiting for manual intervention.

Key architectural changes:
- Coordinator tracked by name in a persisted state file (`sonos-coordinator-state.json`)
- Fallback chain re-roots at the most recently promoted coordinator
- Adoption logic: if a human regroups in the Sonos app, the watchdog picks it up on the next cycle
- SSH failure now detected separately from speaker offline (eliminating false alerts)
- All topology fetched via a single SSH round-trip SOAP call with parallel liveness probes

The race condition from the prior architecture — where `sonos-status.py` would dissolve a watchdog-promoted group within 30 seconds — was eliminated by stripping all group-management code from `sonos-status.py`. The watchdog now owns group management exclusively; `sonos-status.py` handles now-playing tracking only.

### herdr 0.8.2 + Supplies Routing Fix

The herdr SKILL.md was regenerated for protocol 20 (`7252c57eb5`). Supplies shipped-email routing was corrected: Gmail "shipped" emails now route to Tier 3 (informational) rather than Tier 1 (requires action), stopping false-positive action queuing for packages already en route (`f4b5e31726`).

**Lesson Learned:** When two processes share responsibility for the same resource (group management), they will eventually conflict. The fix was not better coordination between them — it was eliminating the conflict by giving one process full ownership. Watchdog owns groups; status script reads state only.

## Day 340: jfdibot's First Autonomous Post and Hybrid Memory Search Ships (September 6, 2026)

### jfdibot: Autonomous Twitter Posting Agent

**Commits `78a1c5e8c4` (agent), `35d52695ab` (bird-jfdibot.sh + cookie sync)**

The jfdibot autonomous posting agent shipped. The system: a scheduled job (`jfdibot-post.cjs`) gathers candidate content from git commits, EOD briefs, handoff summaries, and memory learnings; invokes Claude to score candidates and draft posts; and posts autonomously when confidence is ≥80% (SAFE_TO_POST), or sends to the Discord workbench thread for approval otherwise.

Three-tier guardrail system (`guardrails.json`): `never_post` (competitor mentions, PII, unconfirmed claims), `needs_approval` (borderline, mixed signals, novel claims), `safe_to_post` (operational wins, workflow results, confirmed facts). Voice guidelines: business owner audience, coworker attribution via @alexhillman where natural.

First real test run: content selection working, guardrail scoring confirmed (97% on the first candidate). Daily rate limit hit during testing. `bird-jfdibot.sh` provided the initial posting path, pulling Twitter cookies from the agentcookie store.

### Hybrid BM25 + Vector Search Ships

**Commits `f54d2ba6a5` (implementation), `a98d2bc467` (mxbai→nomic scaffolding, #649 Phases 1+2)**

Pure cosine similarity at threshold 0.30 was returning 97-99% of the 45k memories table for most queries — the threshold was effectively a no-op, leaving ORDER BY + LIMIT as the only relevance signal. The hybrid approach fixes this: `0.7 * cosine_similarity + LEAST(ts_rank * 3, 0.3)`, with WHERE passing if either `vector_sim >= threshold` OR an FTS match exists. Keyword-specific queries now surface exact matches even when vector similarity is mediocre.

Tested on "door code sync history": hybrid returns 3 on-topic memories in the top 3; vector-only slips in tangentially-related lockbox/access memories at positions 2 and 4.

Phase 1+2 scaffolding for the mxbai→nomic embedding migration also landed: `embedding_nomic vector(768)` column added to `memories` and `memory_suggestions`, BackfillEmbeddings command rewritten with `--column/--model/--table` options, nomic `search_document:` prefix support, and model threaded through EmbeddingService and the `/api/embed` endpoint.

### agentcookie: Gmail Snooze List with Cache Freshness Gate

**Commits `cc6726632f` (snooze list), `dc31ba81ab` (selector waits), `e4fb530c67` (exit-code contract)**

The agentcookie Gmail automation gained a `snooze list` command — reads active snoozed emails with a 5-minute cache freshness gate to avoid hammering the Gmail interface on consecutive calls. Selector wait logic added with sleep fallbacks for elements that load asynchronously. The shared exit-code contract adopted from pp-amazon, with a reconcile guard against mass accidental release (preventing a single malformed response from clearing all snoozed messages).

### Handoff Page Redesign + Recovery Brief Enriched

**Commits `dec26d3ac4` (page redesign), `8d6b2941df` (GitHub Issues section), `046e59502f` (boundary embed tracking + unanswered-request directive)**

The handoff page (`HandoffController.php`) received a paper/ink aesthetic redesign: Fraunces serif h2s, DM Sans body, red list markers, blue-shadow code blocks, container-per-section layout. Five new Haiku recovery sections added to `session-recovery.ts`: Files Being Edited, Git/System State, Key Assumptions to Verify, Dead Ends, Handoff Confidence. A GitHub Issues section was added showing open issues the session was working on. The boundary embed now tracks `boundary_embed_msg_id` before calling Haiku — fixing the timing bug where the footer link would sometimes be missing.

### claude-invoker Refactor: Failure Cause at the Source

**Commit `18f1c52580`**

The `claude-invoker.cjs` was refactored to return the failure cause directly, rather than leaving 18 callers to compute it independently from raw output. Failure diagnosis is now centralized — a single change to error detection logic propagates everywhere instead of requiring 18 separate fixes.

**Lesson Learned:** A content-scoring system that can say "I'm 97% confident this is safe to post" enables autonomous action without requiring explicit per-post approval. The three-tier guardrail (never/approval/safe) gives the system a way to act boldly on clear cases while remaining conservative on ambiguous ones — the same principle as the filter-manager confidence scoring built in Week 1.

## Reflection: Week 46

---

### The Mistakes We Made

#### 1. The Orphan Brace That Silently Killed Context-Warning

**Cost:** An orphan closing brace in the context-warning hook was short-circuiting execution on certain paths for an unknown period. The hook appeared to run (no errors reported) but exited early without acting. Sessions that should have received early-warning WARN/CRIT messages didn't — the handoff arm never fired on those paths.\
**Fix:** `18ee4e6205` — brace removed; pre-turn guard and stderr logging added in the same session so future failures surface visibly.\
**Lesson Learned:** A hook that exits early without logging is invisible. The absence of errors is not evidence of correct execution. Every exit path needs a log line.

#### 2. hybrid Search Wired to Endpoint But Not Production Recall

**Cost:** The hybrid BM25+vector search was built and tested in Week 45 — but wired only to the explicit `/semantic-search` endpoint. The actual production recall paths (`relevant()`, `pureSemanticSearch()`) were still running pure vector search. The system had the fix but wasn't using it.\
**Fix:** `c1445c10ad` — flip `hybrid` default to true; replace raw vector SQL in the two production paths.\
**Lesson Learned:** "Available via endpoint flag" is not the same as "in production." A feature gated behind an explicit opt-in flag is only as good as the callers that pass that flag. Verify which code paths actually matter, then wire the feature there.

### The Surprising Things

#### 1. jfdibot Scored 97% on Its First Real Candidate — And Then Hit the Daily Rate Limit

**Expected:** The first autonomous post would require tuning — low scores, multiple review cycles, manual overrides.\
**Actual:** The first real candidate scored 97% (well above the 80% SAFE_TO_POST threshold). The pipeline worked end-to-end on the first attempt. It then hit Twitter's daily post rate limit during testing, deferring the actual first post to the next day.

The system didn't need debugging to work. It needed rate-limit handling to finish.

#### 2. The Boundary Panel Context File Took Three Iterations to Get the Right Format

**Expected:** Posting the injected session context to the thread would be straightforward — one commit, done.\
**Actual:** Three iterations across Days 335-336: plain message → embed panel → expandable file attachment. Each was correct for a different use case; the final format (file attachment) is the right balance between "accessible for those who want it" and "not intrusive for those who don't."

Three iterations in 24 hours isn't failure — it's rapid discovery of the right format.
