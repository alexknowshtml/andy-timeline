## Reflection: Week 20

---

### The Mistakes We Made

#### 1. Knowledge Audit Auto-Fix Revert Cycle

**Cost:** 4 rounds of fix → revert → fix → revert for date prefix corrections, burning commits and cluttering git history\
**Fix:** The auto-fix logic needed to be scoped to only fix unambiguous cases where the date prefix convention was clearly violated, not cases where the filename had a different valid convention\
**Lesson Learned:** Self-healing systems need confidence scoring. If a fix has side effects that require immediate reverting, the fix should have been flagged for human review instead of auto-applied.

#### 2. Session Recovery Infinite Loop

**Cost:** The initial auto-recovery for context-exhausted sessions created an infinite loop where recovered sessions re-queued their own recovery message\
**Fix:** `d14f8e745` and `1528f6122` - check recovery lock before health check, stop re-queuing after recovery\
**Lesson Learned:** Recovery systems must be idempotent. If recovery action A triggers condition B which triggers recovery action A again, you have a loop. Always check "am I already recovering?" before recovering.

#### 3. Discord.js Rate Limiter: Three Attempts

**Cost:** Three commits to solve sluggish Discord button responses, each trying a different bypass strategy\
**Fix:** Raw fetch for Discord API calls in the reaction handler bypassed the queue entirely\
**Lesson Learned:** When a library's safety mechanism becomes the bottleneck, sometimes the answer is to bypass the library for the specific hot path rather than configuring around it.

---

### The Surprising Things

#### 1. PWYW Pipeline: 5 Phases in 3 Days

**Expected:** A multi-phase automation pipeline would take a week or more to build and stabilize\
**Actual:** PWYW went from plan to production-complete in 3 days (Day 156-158), including database tables, webhook detection, Nexudus integration, batch processing, Discord approval flow, and old code removal

The Discord approval pattern established in earlier weeks meant Phase 3 (approval buttons) was almost turnkey. Pattern reuse compounds.

#### 2. Supabase Migration Was Anticlimactic

**Expected:** Migrating a production database from a hosted service to local would be a multi-day, high-risk operation\
**Actual:** The migration itself was a dump, restore, and config change. The 399-line plan was mostly about documentation and fallback procedures, not the migration itself

Database migrations are scary in theory and boring in practice - if you have good backups and clear rollback procedures.

#### 3. Multi-User Buttons Needed Almost No Architecture

**Expected:** Supporting multiple users in a single Discord thread would require major architectural changes\
**Actual:** User-scoped buttons were mostly a matter of tracking who sent which message and filtering button visibility. The existing infrastructure already had the right hooks.
