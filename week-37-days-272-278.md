## Day 275: Calendar Engineering Marathon (July 3, 2026)

### Five Calendar Sync PRs in One Day

**Commits `e01a0e4df4`, `417f4832d9`, `6f6e41d894`, `1aa5288933`, `856cb11a50`**

The calendar sync system received five pull requests, each fixing a distinct failure mode in the merge resolution layer:

- **PR 1** (`e01a0e4df4`): EventObserver hardening + false-sync migration — observers that triggered on unrelated changes no longer fire calendar pushes
- **PR 2** (`417f4832d9`): Merge path consolidation + resurrection loop fix — deleted events reappearing in GCal was a recurring issue; the resurrection guard closes it
- **PR 3** (`6f6e41d894`): `gcal_push_hash` echo suppression + push path consolidation — two separate push paths had diverged in behavior; one path now
- **PR 4** (`1aa5288933`): Deletion approval gate via Discord buttons — GCal deletions now surface for human review before the DB record is touched
- **PR 5** (`856cb11a50`): iCal hash regex + cancelled status preservation — iCal UIDs with edge-case formats were triggering false deletes

Then `39b9ddb672` added GCal→DB reverse sync via native API: changes made directly in Google Calendar now propagate back to the database. The calendar sync model became bidirectional.

**Lesson Learned:** A bidirectional sync system's bugs cluster in the merge resolution logic. Five PRs in one day is a sign you found the cluster — merge, test, and declare the field-ownership model stable before adding features on top.

### Compaction-Tracker Module (GH #289)

**Commits `370fd2ebbf`, `80688f02c4`, `7502b27d4e`, `0977e23f45`**

The host-bridge compaction display logic — which had accumulated ad hoc dedup patches across multiple sessions — got extracted into `compaction-tracker.ts`: a proper module with a Vitest test suite. The extraction immediately exposed the root cause of the duplicate "Compressing context..." post: the transcript-watcher cross-spawn fallback was writing to a stale thread map. Four fix commits followed before the module was stable.

**Lesson Learned:** When you've applied three or more patches to the same bug in the same file, stop patching and extract. A module with its own tests makes invariants explicit and regressions detectable.

### XState Shadow Coverage: Gaps 1 and 2 Closed

**Commit `dbcbeb4f8e`**

Two weeks of shadow-mode running on the spawn-lifecycle XState machine surfaced two gap cases — state transitions the imperative code handles correctly but the machine model didn't represent. Both gaps were closed with new states and transitions. The machine model is now divergence-free on observed production traffic.

**Lesson Learned:** Shadow mode works exactly as advertised. You can't unit-test edge cases you haven't imagined, but two weeks of real production traffic imagines them for you.

### Relationship Flags Get a Triage Queue

**Commits `c03fa2aeb4`, `c2ec54b6d8`**

The `/review-relationship-flags` command was added with a dedicated triage workflow, and the scheduled job was updated to run the flags review automatically. Previously flags accumulated in audit summaries with no follow-up queue — the same flags recurred across runs indefinitely. The new command surfaces them as an actionable list.

**Lesson Learned:** A flag that isn't routed to a triage queue isn't a flag — it's a log entry. The value of flagging is in the follow-up, not the detection.

### Cascade-Close on Project Deletion

**Commit `7d8a61e177`**

Andy Core gained cascade-close behavior: when a project is deleted, all its incomplete tasks are automatically closed. Previously deleted projects left tasks dangling — the PM agent would try to close them and fail with 404s because the project no longer existed.

**Lesson Learned:** Referential integrity in a task system requires cascade operations. Deleting a parent record without closing its children creates orphaned tasks that can never reach a terminal state through normal workflows.

**Commit `673406d7e2`**

**Lesson Learned:** A documented rule the model can ignore isn't a rule — it's a suggestion. Hooks that enforce at the tool layer are the only durable enforcement.

### Discord Tables Get Auto-Converted

**Commit `8cb093fa6c`**

Any agent output containing a markdown pipe table is now detected and reformatted into the `+===+` grid format wrapped in triple backticks before posting to Discord. **Lesson Learned:** Fix display problems at the transport layer, not by asking every producer to change format. One conversion in the Discord service is more reliable than 20+ agents remembering a Discord-specific rule.

## Day 277: Voice Memo Pipeline, Zero to Production (July 5, 2026)

### The Voice Memo Pipeline Built in One Day

**Commits `3984ad67fe`, `1f86ce0820`, `7a62d14831`, `13116389d3`, `5f1d1b0780`, `b7a7eb1e3e`, `849873d91d`, `c68ce1f5a6`, `561fba593d`, `b3c7f58474`**

On July 4, voice.indyhall.org was live and meetily was transcribing. On July 5, the voice memo pipeline was built around it — from nothing to a production system in a single session.

The pipeline that landed:

1. **Mac Mini watcher** detects new `.qta` recordings and queues them
2. **AssemblyAI transcription** runs at detection time, not at button-click time
3. **Page pre-staging**: a 6-char hex token is generated, the audio file is downloaded from Mac Mini and uploaded to DO Spaces as `meetings/{TOKEN}/audio.m4a`, the page folder is created — all before the Discord panel appears
4. **Discord panel** shows immediately with a 🎧 Listen link (audio is already on Spaces)
5. **Haiku generates the title** using the full transcript with a TV episode logline prompt — one core decision, no small talk
6. **Haiku generates a 2-sentence preview** (stripping `[HH:MM:SS] SPEAKER_NN:` prefixes before sending)
7. **Calendar lookup** enriches the title with the event name and attendees (Alex's calendar first, IH 709 as fallback)
8. **Speaker diarization** runs through the full pipeline (pyannote → `{SPEAKER_NN}` labels)
9. **Atomic state writes** prevent partial-update corruption
10. **Completion callback** fires when done; orphan replay threads prevented by dedup guard

The key architectural decision: do as much work as possible before the user clicks anything. By the time the Discord panel appears, the audio is already uploaded, the title is generated, and the page folder exists. The button click is authorization, not initiation.

**Lesson Learned:** The user shouldn't wait for work that can be done proactively. Front-load everything computable before user interaction — the interaction becomes instant, and perceived latency vanishes.

### GMeet Pipeline Unified (GH #343 Steps 1-4)

**Commits `609dbcdf04`, `24244fa1e3`, `06eb5cf8ac`, `aa98ed30fe`**

The GMeet pipeline had three separate publishing paths that had diverged in behavior. GH #343 restructured the whole system in four steps:

- **Step 1** (`609dbcdf04`): meeting-replay becomes the unified publisher for all GMeet recordings — Drive download stays in the gmeet command, but everything after is delegated to the skill
- **Step 2** (`24244fa1e3`): Unified replay state store replaces per-source JSON files — all recording types share one state model with `gm-{docId}` and `vm-{hash}` prefix namespacing
- **Step 3** (`06eb5cf8ac`): Full pre-staging in the poll script — when AssemblyAI finishes, the poll immediately pre-stages the page (token, folder, audio upload) without waiting for user confirmation
- **Step 4** (`aa98ed30fe`): Watchdog extracted to a standalone job (`meeting-replay-watchdog.cjs`) running every 5 minutes, removed from the poll loop entirely; dual-writes to both legacy and unified state to prevent the sync revert loop (Fable finding #1)

**Lesson Learned:** When a pipeline has multiple publishing paths, unify the publisher before fixing bugs in any individual path. Bug fixes applied to three paths need to be applied three times; one path needs fixing once.

### Dangerous-Command-Guard: 18 Fixes from Fable Review

**Commit `e8f5879cef`**

A Fable model review of the dangerous-command-guard script (GH #339) found 18 issues: false positives on date-prefixed slugs treated as credentials, a heredoc stripper missing alternate heredoc forms, broken reroute JSON, and missed dangerous patterns (pm2 stop/delete all, flag-credential in equals/quoted forms, Authorization Bearer reroute). All 18 were applied in one commit.

**Lesson Learned:** Security scripts need adversarial review, not just functional review. A guard that blocks the wrong things (false positives) and misses real patterns (false negatives) provides false confidence. An outside reviewer with a refutation mandate finds both failure modes.

### The Mistakes We Made

#### 1. dangerous-command-guard: 18 Gaps Discovered in Production

**Cost:** A security hook running in production had 18 defects: false positives on benign patterns, false negatives on real dangerous commands, and broken JSON output on the reroute path. Any false negative could have allowed a credential leak or destructive command through.\
**Fix:** Applied all 18 fixes in one commit after the Fable adversarial review (`e8f5879cef`, GH #339).\
**Lesson Learned:** Security gates need adversarial review before they ship, not after. Writing the guard and writing the review prompt for the guard should happen in the same session.

#### 2. Voice-Memo Title Generation Sampled a Partial Transcript

**Cost:** Early voice-memo title generation skipped the first 10% of the transcript and sampled at 2x density — which consistently missed the key decision or theme if it appeared in the skipped section. Titles were generic.\
**Fix:** `fea8bd067e` — switched to using the full transcript.\
**Lesson Learned:** Optimization before correctness is premature. Sampling saves tokens but only if the sample is representative. For title generation, the core insight can appear anywhere.
