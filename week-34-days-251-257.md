## Day 251: Status Sequences and Newsletter Day (June 9, 2026)

### Frozen Clocks and Consumed Turns

**Commits `fa93ab4c0`, `ea3d2dc73`, `26a7de7f4`**

Two distinct host-bridge bugs surfaced post-migration. The first: a frozen spinner showing stale timestamps. Root cause: all status updates for a turn shared one sequence counter, so concurrent updates from tool calls and status heartbeats went out of order — the last-seen sequence pinned to a stale value. Fix: per-session sequence tracker so each concurrent turn gets its own counter. The live-clock status suffix feature that had shipped as part of the same session was reverted that same day after the per-session fix made it redundant.

The second: compaction events were consuming a turn's content without sending the assistant message. Host-bridge now detects compaction mid-turn, emits an honest "⏳ compressing context..." status, and queues the resumed turn for delivery.

You also removed the elapsed timer and heartbeat loop from the subagent watcher that was adding noise without value — a cleanup that stayed in place until the subagent wait work on Day 257.

**Lesson Learned:** Status sequence bugs are invisible in normal usage and only surface under concurrent load. Shared counters are wrong by default for concurrent systems — isolate sequence state per session from the start.

## Day 253: The Message Field Discovery (June 11, 2026)

This was the week's pivotal moment. During a trace report session, Alex saw only buttons — the preceding analysis had been swallowed. ### TurnRegistry: 12 Tests Before the Next Change

**Commit `52a84f34a`**

The Discord bridge's cross-talk/stale-sequence decision logic lived inside a 1,948-line `start.ts` with the Discord client woven through — untestable. The last cross-talk fix (Group A) had shipped untested and broken production within minutes.

The fix was structural: extract `TurnRegistry` as a pure module with zero Discord client imports. 12 characterization tests locked in the current behavior — including known quirks C1/C2, ownership flapping, and seq pinning — so any change to cross-talk rules is now verifiable before deploy. Commit `74b597981` added a per-turn `ANDY_TURN_TOKEN` to all status updates, enabling the turn-based ownership tracking that cross-talk detection needs.

**Lesson Learned:** The cost of "ship untested → break prod → fix → ship" is higher than "add 12 tests → verify → ship." The untestable module was always the risk; the production break just made it undeniable.

## Day 254: The herdr Patch Automation Marathon (June 12, 2026)

### Replacing a Weekly Ritual With a CI Pipeline

**Commit `f349a5b26`**

The herdr fork carries a local patch (tab-target-label) that must be rebased onto every upstream release. The process was: wait for a new upstream tag → hand-rebase the patch → build → verify label-close behavior → install. Fragile, manual, and easy to fall behind on.

You replaced it with GitHub Actions: `patched-release.yml` on `alexknowshtml/herdr` monitors upstream tags, rebases the patch automatically, builds using upstream's exact recipe, verifies label-close behavior against an isolated server, and publishes a `vX.Y.Z-patched` release with its own `latest.json` manifest. The `herdr-update.sh` script now switches manifest sources based on the PATCHED marker.

A companion nightly job (`herdr-manifest-drift`, `1c8927ff0`) runs at 4am ET to detect when the remote manifest has moved past the override's base version and automatically rebuilds the override from a source-of-truth custom rules toml. The claude.toml override is version-controlled via dotfiles symlink with a public gist mirror (`e5362adae`).

**Lesson Learned:** When a maintenance task recurs weekly without variation, it's not a task — it's a missing automation. The 30-minute weekly rebase ritual became a CI job in one day.

### Hook Infrastructure Overhaul

**Commits `87ecf4be7`, `8363c6299`, `45d90655a`, `7a6a329cf`**

Four hook fixes that had been partially broken since the jfdi migration:

1. Hook output was routing through stdout instead of the channel the model actually reads — fixed by using `additionalContext` rather than plain stdout
2. Heredoc content inside `git commit -m "$(cat <<'EOF'..."` was triggering the dangerous-command pattern matcher — fixed by stripping heredoc content before matching
3. CLI text-mode suggest-options instructions weren't reaching the model — fixed by delivering via `decision:block`
4. herdr UI now shows "compacting" during context compression events

All 19 scheduled job files got explicit `[ANDY-INTERNAL-TASK]` prefix added to prompts, replacing the fragile invoker-magic approach where the prefix was injected based on source detection.

**Lesson Learned:** Hooks that route output to the wrong channel are the same as hooks that don't fire. Before debugging hook behavior, verify the output path.

### Compaction Killer Incident Documented, Timeout Chain Fixed

**Commits `455b8b169`, `79d4a4875`**

The compaction killer incident (herdr's orphan reaper closing compacting Claude sessions) got a formal incident report documenting the root cause chain. The fix had already shipped in week 33; the report closed the loop.

Separately, host-bridge and scheduled-job outer kill timers had been set independently of jfdi's `--timeout` ceiling, making it possible for the host-bridge timer to fire before jfdi's own — canceling a session still within its budget. Fix: derive all outer kill timers from `jfdi's --timeout + 120s grace` rather than independent values.

A nightly Claude Code update job (`bcc91dddd`) shipped to detect new versions and post changelog summaries to Discord — the first automated meta-maintenance job for Claude Code itself.

**Lesson Learned:** Timers set independently of the thing they're guarding will drift. Derive from the source, add grace — never set independently.

## Day 257: Injector Hardening + Beads Wind-Down (June 15, 2026)

### The Suggest-Options Injector: Five Iterations in One Day

**Commits `7251276f3`, `b264a74f3`, `54bd541a3`, `46b6438e0`, `47e420d64`**

The PreToolUse hook that auto-injects preceding text (Day 256) required five refinements to handle production edge cases:

1. **Fixed sleep → snapshot poll**: the original used `sleep 2` before reading the JSONL transcript. Under load, the write hadn't completed. Replaced with snapshot-based polling that waits until the byte count stabilizes.
2. **Skip code blocks and short text**: the injector was picking up bash snippets and one-liners as "preceding text" instead of narrative content.
3. **Skip suggest-options entries when scanning backward**: the transcript reader was picking up the suggest-options call itself as context.
4. **Restore early exit when message is already substantial**: a logic inversion was overriding good messages instead of preserving them.
5. **Don't edit fresh streamed text**: a final edge case with flushed-but-not-committed streamed text.

Simultaneously, five protocol-level commits refined behavior: require 100+ char message field, message field always wins over prior streamed text, extract from JSONL tool_use block at detection time, improve error message to emphasize decision context, don't edit fresh streamed text.

**Lesson Learned:** A hook that reads transcript state is inherently racy with the process writing it. Snapshot polling + byte-count stabilization is the correct model for any hook that reads recently-written files.

### The Mistakes We Made

#### 1. The Suggest-Options Hook Needed Five Iterations

**Cost:** The auto-inject hook shipped June 14 with a fixed `sleep 2` for transcript stabilization, inverted threshold logic, and no guard against code blocks as "context." The June 15 session exercised all three issues in sequence — each fix revealed the next edge case.\
**Fix:** Snapshot-based polling, skip-code-blocks guard, skip-suggest-options-entries guard, restore early-exit when message is already substantial.\
**Lesson Learned:** Hooks that read recently-written files need polling, not sleep. The correct model is "wait until the file stops changing" — not "wait N seconds and hope."

#### 2. The Subagent Wait-for-Completion Was Reverted Same Day

**Cost:** GH #90 (subagent wait-for-completion) was implemented and verified in logs, then reverted when the parked-turn handling downstream surfaced an incompatible assumption.\
**Fix:** Reverted; the fix returns once parked-turn handling is resolved first.\
**Lesson Learned:** Host-bridge changes that touch session lifecycle have downstream effects in the parked-turn system. Test the full session lifecycle end-to-end before shipping.

#### 3. Hook Output Was Routing to the Wrong Channel (June 12)

**Cost:** PreToolUse/PostToolUse hooks with plain stdout output were not reaching the model at all. The hooks were "working" in the sense of not erroring, but their messages were invisible.\
**Fix:** Route hook output through `additionalContext` or `decision:block` depending on intent; never plain stdout.\
**Lesson Learned:** "The hook runs" and "the hook works" are different things. Verify the model actually received the hook output before declaring it operational.
