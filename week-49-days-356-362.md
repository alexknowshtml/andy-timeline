## Day 361: GH #799 — Token Usage Gets Its Reckoning (September 27, 2026)

### Token Usage Overhaul: Three Phases

GH #799 landed as the most significant data pipeline work since the PostgreSQL migration in Week 20. The problem: ccusage only reads local `~/.claude` JSONL, so per-day history vanishes when those files are cleaned up; session token counts were 2× the billed figure; fork subagents were never ingested; the incremental cutoff permanently dropped files when a run hit `--limit`. Three phases shipped in a single day.

**Phase 2 — Server-Side Cost Math: Commit `00a7073934`**

The frontend carried its own price table that had drifted from Anthropic's published rates and had no entries for the 5.x models. `config/claude_pricing.php` now carries 14 models with input/output/cache-write/cache-read rates. `ClaudePricing` service uses exact ID or ID+date-suffix match only — an unknown model shows as unpriced rather than borrowing a neighbor's rate. The React components now only display costs the controller computed. A `claude:check-pricing` command and daily 7:10am ET job flag any model in the data without a price entry.

**Phase 3 — Dedup'd Usage and Per-Session Cost: Commit `f5ea70b8f3`**

`SyncSessions` now uses `TranscriptUsageParser`, the shared parser that counts each API response exactly once. It stores `cost_usd` from `ClaudePricing` and writes `claude_session_daily_usage` rows per day and model. Fork subagents are now ingested (parent ID from the fork-context-ref line). The incremental cutoff was fixed: files sorted oldest-first, cutoff advances only on error-free runs. Prior `backfill-tokens` commands that summed every line — and produced the 2× inflation — were removed.

**Phase 1 — Durable Daily Table: Commit `5b124ccd74`**

`claude_usage_daily` — one row per ET day and model — stores hourly snapshots from ccusage. A stored day is only replaced by figures at least as large; it is never deleted. The `track-claude-usage` job pipes the last 7 days in after its weekly snapshot. 96 rows were backfilled from 2025-11-25 to 2026-09-27 from ccusage's still-available history.

### Herdr Restart Hardening

**Commits `66ddd68396` (OnFailure), `02abbf03dc` (podman-conmon rescue), `9039465401` (e2e test), `ea9ab76f37` (read-only check), `9ee264c78d` (pm2-safe-restart fix)**

Sunday's scheduled herdr restart failed silently: `node` wasn't in systemd's PATH, so `pm2-safe-restart.sh`'s env filter step crashed without alerting. Four fixes:

1. **`systemd-failure-notify.sh`**: OnFailure notifier that posts failed user units to Discord; units now set PATH explicitly.
2. **Podman-conmon rescue** (`02abbf03dc`): `pasta` is rescued from herdr's cgroup on restart so container networking survives the restart.
3. **E2E test** (`9039465401`): Restarts herdr from outside and probes both a rootlessport-backed and pasta-backed test container.
4. **Read-only check** (`ea9ab76f37`): One command to confirm Sunday's restart ran, rescue completed, and nothing was left behind.

### Other Fixes

- `481d867335` — suggest-options: match sentinel only in the call's own tool_result
- `dd627f8eb8`, `48e4bd14c6` — s3-upload MIME: `.mov` → `video/quicktime`, `.mp4` → `video/mp4`
- `6898bddd5f` — PM Step 4.5: readiness check for every event within 48 hours

**Lesson Learned:** A systemd unit that fails silently is as dangerous as a service that fails silently. `OnFailure=` should be standard on any unit Andy depends on for weekly operations. It took a missed restart to make that obvious.

### Backup Truncation Crisis Fixed

**Commit `9e8dc83987`**

A critical find: every offsite `andy_core` pg_dump since approximately September 6 had been truncated. Spaces showed 7.8 GB vs 11.4 GB local, no gzip trailer — a partial file uploaded as if complete. The cause: `pg_dump` ran under a 300-second timeout silently swallowed as "completed with warnings," then whatever partial file existed was uploaded without verification.

Four fixes:
1. pg_dump timeout 5 min → 30 min, `pipefail` set, any failure deletes the partial file
2. `pigz -t` integrity check before upload
3. Upload verify: compares Spaces `ContentLength` to local size
4. Upload and wrapper timeouts increased significantly

The gotcha: `pigz` kept writing after the shell was killed, so the local copy looked complete while the Spaces copy was truncated.

### Shared Screenshot Script

**Commit `acdf7e781a`**

`scripts/jfdi-screenshot.py` landed as a shared Playwright script that pre-mints Alex's session cookie and pre-sets hint and alert dismissal keys. Every session that needed a screenshot had been hand-rolling a fresh Playwright context, causing the "Hold for quick menu" first-visit hint to appear in every app screenshot. The andy-core-dev skill now points to the shared script.

**Lesson Learned:** A 300-second timeout that swallows `pg_dump`'s non-zero exit code is worse than no timeout — it produces a false "completed" signal while silently accepting truncated output. `pipefail` and a size check before upload are the baseline for any backup script that needs offsite confidence.

## Reflection: Week 49

---

### The Mistakes We Made

#### 1. pg_dumps Silently Truncated for 22 Days

**Cost:** Every offsite `andy_core` backup since approximately September 6 was truncated — 11.4 GB locally vs 7.8 GB in Spaces, no gzip trailer. Every restore from Spaces during this window would have failed. The backup job reported success throughout.\
**Fix:** `9e8dc83987` — 30-min timeout, `pipefail`, partial file deleted on failure, `pigz -t` integrity check, upload size verification.\
**Lesson Learned:** A backup pipeline without output verification creates a false sense of confidence. Size check and gzip trailer validation should be the final gate before any backup is marked complete.

#### 2. systemd PATH Doesn't Inherit Shell PATH

**Cost:** The weekly Sunday herdr restart failed silently because `node` wasn't in systemd's PATH — `pm2-safe-restart.sh` crashed and nothing alerted. Failure was only discovered on manual inspection.\
**Fix:** `66ddd68396` — `systemd-failure-notify.sh` OnFailure notifier + explicit PATH in unit files.\
**Lesson Learned:** systemd user units run in a minimal environment. Any unit that depends on a PATH-resolved binary needs `Environment=PATH=...` set explicitly, or it silently fails in ways that look like success.

### The Surprising Things

#### 1. The Skills Listing Had Been Broken for Months

**Expected:** Skill descriptions were being used for routing context as designed.\
**Actual:** At 117k characters against an 8k budget, every description was being dropped — Andy had been routing by name alone for an unknown length of time. The problem produced no visible error or degradation signal. A single commit (budget raise + name-only overrides + description rewrite) fixed routing quality that had been quietly degraded since the skills list grew large enough to overflow.

#### 2. Session Token Counts Were 2× the Billed Figure

**Expected:** The sessions table's token counts were roughly accurate.\
**Actual:** Fork subagents were counted multiple times and the usage parser was summing every line rather than counting each API response once. The Anthropic-billed figure was roughly half what the sessions table showed. The `TranscriptUsageParser` dedup fix corrected years of inflated reporting.
