## Reflection: Week 22

---

### The Mistakes We Made

#### 1. ESM/CJS Naming Broke 12 Jobs Overnight

**Cost:** 12 scheduled jobs failed silently after the config consolidation introduced a `.js` file with `require()` syntax in an ESM-configured directory\
**Fix:** `3c6c7fbc4` - Renamed to `.cjs` and updated all require paths\
**Lesson Learned:** In a `"type": "module"` package, every `.js` file is ESM. If you need CommonJS, use `.cjs`. This is a one-line rule that prevents cascade failures.

#### 2. Misresolved Contacts in Early Batches

**Cost:** "Geo" was matched to the wrong person before being identified as Giovanni Cortes via Stripe receipt. Several contacts had to be manually corrected after automated resolution.\
**Fix:** `a323a709f` - Added business-name detection and tightened matching thresholds\
**Lesson Learned:** Contact resolution confidence scores need a "maybe wrong" zone. When the match is plausible but not certain, flag it for review instead of auto-matching.

#### 3. Morning Overview Job Dying Silently

**Cost:** The morning overview email wasn't arriving because the job was hitting a 2-minute timeout and dying without logging\
**Fix:** `d05e65718` - Bumped timeout to 25 minutes and added session-file fallback\
**Lesson Learned:** Every scheduled job needs two things: a timeout that matches its actual runtime, and a failure notification. Silent death is the worst failure mode.

### The Surprising Things

#### 1. 151 Contacts Resolved in Two Days

**Expected:** iMessage contact resolution would be a multi-week background task\
**Actual:** The resolver agent + orchestrator pattern processed all 151 contacts in 5 batches across 2 days, with person file creation and Gmail enrichment happening inline

The batch-and-cascade pattern made this tractable: most contacts matched on phone or name (fast), and only the genuinely ambiguous ones needed Gmail research (slow).

#### 2. Config Consolidation Touched 30+ Files

**Expected:** Centralizing Discord channel IDs would be a straightforward config file + a few imports\
**Actual:** Channel IDs were hardcoded in 13 scheduled jobs, 6 PHP files, multiple skills, and agent-facing commands. The consolidation required a 4-phase migration with language-specific loader modules.

Hardcoded values don't feel like tech debt until you try to change them all at once.

#### 3. Unified Search Surfaced Integration Gaps

**Expected:** Wrapping 14 data sources in one skill would be primarily a routing exercise\
**Actual:** Building the unified search revealed that several sources (Front, Beeper, sparks) had inconsistent query interfaces and result formats. The wrapper forced standardization.
