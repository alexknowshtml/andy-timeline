**Commits `5edafdb585`, `743235840`**

## Day 249: jfdi Phase 6 Completes — All of Andy Core Flips (June 7, 2026)

**50+ significant commits**

### The Flip That Finished the Migration

**Commits `15b6d7b86` (route Claude spawns), `1d6b02f0b` + revert `f9124ae7e` (Phase 6 Discord), `8232654e9` + revert `02b49d8c6` (CLAUDE_PATH), `5a49d86675` (all jobs USE_JFDI), plus 8 host-bridge parsing fixes**

Week 32 did `scripts/`. Day 249 did Andy Core itself: `CLAUDE_PATH` flipped to `jfdi`, all scheduled jobs migrated to `USE_JFDI=1`, and Discord spawns routed through jfdi/herdr.

The flip required two reverts and retries. jfdi streams coarse JSONL events — not the fine-grained `content_block` events the raw `claude` CLI emits. Host-bridge needed to learn the new format: parse `tool_use` from jfdi assistant events (`780584c04`), extract text from the right event type (`4ba03109d`), finalize Discord messages on `stop_reason=end_turn` instead of output-sniffing (`cd21b442f`), and route `classify`/`thread-name` calls through jfdi with the herdr socket (`29dcc8893`).

After the fixes landed, every Claude call in the system — scripts, scheduled jobs, Discord conversations, graph probes — routes through one invoker.

**Lesson Learned:** Switching the invocation layer exposes every assumption the rest of the system made about output format. Budget a "parse the new format" commit cluster for every invoker flip — it's not a regression, it's expected work.

### The catch-memories Self-Loop

**Commits `054d22dbba7` (exclude scheduled sessions), `654990032` (break probe-graph loop)**

A subtle infinite loop surfaced during the jfdi migration. `catch-memories` processes sessions and triggers the memory-graph-gate hook. The hook calls `probe-graph`. `probe-graph` spawns jfdi *without* the `[ANDY-INTERNAL-TASK]` prefix — so those sessions land with `source='interactive'` and re-enter the `catch-memories` queue. Which processes them. Which triggers the hook. Which calls probe-graph. Indefinitely.

Two-layer fix: the gate hook now skips the probe entirely when the user message starts with `[ANDY-INTERNAL-TASK]`, and the probe prompt template now includes the prefix so even if the hook somehow fires, the session gets `source='scheduled'` and is excluded from catch-memories processing.

**Lesson Learned:** When the system processes its own outputs as inputs, the fix must live at both ends. Tag internal tasks at injection and filter at detection — one layer leaves the other entry point open.

## Reflection: Week 33

---

### The Mistakes We Made

#### 1. Launched on the Wrong SMS Carrier

**Cost:** Two-way SMS launched on VoIP.ms on Day 244. By Day 246, the 10DLC campaign was rejected — missing privacy page, wrong campaign description. Two days of SMS infrastructure thrown away.\
**Fix:** Pivoted to Telnyx and added a scheduled `check-10dlc-campaign.cjs` job to monitor compliance status going forward.\
**Lesson Learned:** 10DLC registration requirements aren't a footnote. Check carrier compliance requirements before committing to infrastructure. The two-day pivot cost two days; checking first would have cost an hour.

#### 2. The Invoker Flip Required Two Reverts

**Cost:** Both the `CLAUDE_PATH` flip and the Discord spawn routing needed a revert-and-retry cycle. The first attempts didn't account for jfdi's coarse event format versus the raw CLI's fine-grained `content_block` events.\
**Fix:** Added a cluster of host-bridge parsing fixes between the two attempts.\
**Lesson Learned:** Test the new event format in isolation before flipping production. The coarse vs. fine distinction was knowable from jfdi's docs; the two reverts were avoidable with a single test pass first.

---

### The Surprising Things

#### 1. The catch-memories Self-Loop Was Architecturally Hidden

**Expected:** The jfdi Phase 6 migration would surface format-parsing issues in the output layer.\
**Actual:** It also surfaced a source-tagging loop where internal probe sessions re-entered the catch-memories queue because the `[ANDY-INTERNAL-TASK]` prefix was missing from the probe prompt.

The loop had probably been running at low volume for weeks — the migration just made it visible by increasing the frequency of probe sessions. The fix was two lines, but finding it required tracing the full session lifecycle from catch-memories through the hook through the probe and back.

#### 2. The Wine Rack Scope Expanded Naturally

**Expected:** Moving wine-rack.html from /tmp to the repo — a 30-minute commit.\
**Actual:** 25+ commits, a complete production app with filters, search, pairings, price lookup, collection valuation, 56-wine notes backfill, and mobile polish.

The scope expansion happened commit by commit, each one revealing the next obvious improvement. This is how personal tools should evolve: each commit makes the next one obvious.
