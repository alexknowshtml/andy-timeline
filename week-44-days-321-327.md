**Commits `c5ed23716a` (agent + preferences layer), `478b54915d` (history lookup + cart + auth), `b75ad8d5cb` (search discovery flow), `5234b0a0d0` (product photos in results), `d84299856e` (warning handling), `838075fb22` (JFDI cart mutation guards), `3a002c81a4` (account reporting), `4206e81760` (personal profile restriction), `f89f79a452` (per-unit price), `ae01a72007` (amazon order intent), `e9667e9d4a` (docs)**

- **Layer 1:** Agent must see the literal word "JFDI" before calling any cart mutation. No other phrasing counts.

## Day 326: OpenHistory Tunnels, /work-on, and a Watchdog Race Fix (August 23, 2026)

### OpenHistory: PM2-Managed SSH Tunnels for Mac Activity

**Commits `034cb2e6a6` (PM2 SSH tunnels), `9e4656e40a` (sync job + EOD integration)**

OpenHistory MCP — a browser history server running on the Mac Mini — became reachable from Hetzner via PM2-managed SSH tunnels. Two tunnel processes registered in `ecosystem.config.cjs`: port 47831 for Mac Mini, port 47832 for MacBook (gracefully unavailable until Remote Login is enabled). The tunnels auto-restart on drop.

The EOD integration is the payload: a `sync-openhistory.cjs` job polls both tunnels every 30 minutes and writes JSON snapshots to `~/.andy-state/`. Step 1.6 of the EOD command now reads both device snapshots before Opus synthesis — so Alex's browser activity on the Mac joins calendar, reminders, emails, and relationships in the evening briefing, even if the Mac is asleep at 6pm.

### system-watchdog: Snapshot Race Fixed

**Commit `75660714c3`**

A subtle race in the system-watchdog was emitting spurious "claude_count exceeds claude_total" advisories. Two separate `ps` calls were counting interactive vs. total Claude sessions — but a session could exit between the two calls, making the interactive count appear higher than the total. The fix snapshots `ps` output once and derives both counts from the same data. A secondary gotcha: `wc -l` returns 1 on empty input, so the empty-snapshot case needed an explicit guard.

## Reflection: Week 44

---

### The Mistakes We Made

#### 1. TikTok CDN URL Landing in Body Instead of Frontmatter

**Cost:** The initial TikTok CDN commit placed the video URL in the reference file body, inconsistent with the structured frontmatter pattern the rest of the pipeline uses. Two follow-up commits were needed to move it to frontmatter and fix the path.\
**Fix:** `27760aedb2` moved the CDN URL to frontmatter; `7a13537283` corrected the exact transcript path from `transcribe-smart.sh` output.\
**Lesson Learned:** When adding a new field to a pipeline's output format, check where analogous fields live (frontmatter vs. body) before the first commit lands. Two-commit corrections for placement are avoidable.

#### 2. system-watchdog Count > Total Spurious Advisory

**Cost:** The watchdog was emitting false "claude_count exceeds claude_total" notifications — a condition that's logically impossible but could appear real if two `ps` calls ran with a session exit between them.\
**Fix:** `75660714c3` — snapshot `ps` once, derive both counts from the same output. Explicit guard for `wc -l` empty-input edge case.\
**Lesson Learned:** Any two-call probe of a changing process table is a race. Count and total derived from separate `ps` runs can never be consistent — one snapshot is the only correct approach.

---

### The Surprising Things

#### 1. The Shopper Agent's Three Safety Layers Emerged Organically

**Expected:** Cart mutation safety would be a single confirmation step — "are you sure?" before checkout.
**Actual:** Three independent layers emerged from working through the failure modes: agent-level (JFDI gate), profile-level (Discord ID restriction), and CLI-level (--confirm-phrase flag). Each layer catches a different class of mistake. The CLI flag in particular — a shell-level reject on empty phrases — means even a confused agent can't trigger a cart mutation by passing nothing.

The layered safety model wasn't designed top-down. It accumulated as each failure mode was identified and the most appropriate interception point became obvious.

#### 2. OpenHistory's Value Is in Caching, Not Live Connection

**Expected:** The main OpenHistory use case would be on-demand queries: "what did I look at today?" during an active session.
**Actual:** The EOD integration reveals the real value is in scheduled polling and disk caching. Mac devices sleep; connections drop; the 6pm EOD brief can't depend on a live tunnel. Polling every 30 minutes and writing snapshots makes the data available at briefing time regardless of device state. The on-demand tunnel is useful but secondary.
